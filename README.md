# jvmti-lab

Код к циклу статей на Хабре «JVMTI в Android: вскрываем HackMe и учимся не делать так же».

JVMTI — служебный интерфейс виртуальной машины, на котором стоят отладчик и профайлер Android Studio. Через него видно, что на самом деле лежит в памяти приложения и что делает его код. А раз это может увидеть автор приложения, может увидеть и атакующий.

В репозитории лежит подопытное приложение **VaultNotes** с намеренными уязвимостями и спрятанными флагами, локальный сервер для него и JVMTI-агенты на C++, которыми мы эти флаги достаём. К концу цикла агенты складываются в аудитор безопасности, который можно натравить на своё приложение.

> ⚠️ Всё в этом репозитории предназначено только для учёбы и аудита **своих** приложений. VaultNotes уязвим нарочно: не копируйте его код в настоящие проекты. Агенты работают только с debuggable-сборками и никогда не должны попадать в release.

## Легенда: VaultNotes

VaultNotes — «защищённые» заметки: вход по логину и PIN, поиск по заметкам, премиум-подписка с оплатой картой и справка во WebView. Внутри живёт встроенный «сторонний» SDK аналитики со своими грехами. Приложение собирается с R8 (minify + full mode), но остаётся debuggable, поэтому все агенты работают против обфусцированной сборки.

Всего в VaultNotes спрятано 14 флагов: от токена, который остаётся в памяти после выхода, до проверки премиума, которую клиент делает сам, игнорируя сервер. Список без спойлеров лежит в [FLAGS.md](FLAGS.md).

## Структура

```
jvmti-lab/
├── crackme-vaultnotes/   # подопытное Android-приложение VaultNotes (HackMe)
│   ├── app/              # экраны, сеть, премиум; src/main/cpp — libvault.so (PIN и секреты)
│   ├── analytics-sdk/    # встроенный «сторонний» SDK аналитики
│   └── data/             # Room/SQLite: заметки, кэш ответов, сессия
├── server/               # локальный сервер на Ktor: логин, заметки, оплата, проверка премиума
├── agents/               # JVMTI-агенты на C++
│   ├── common/           # общий каркас: RAII-обёртки, логирование, JSON-отчёт
│   ├── part1-recon/      # часть 1: разведка (классы, загрузчики, native-методы)
│   ├── part2-memory/     # часть 2: секреты в куче
│   ├── part3-behavior/   # часть 3: поведенческий аудит
│   └── part4-hidden/     # часть 4: динамический код, native-секреты, клиентские проверки
├── auditor/              # итоговый аудитор: JSON-правила и HTML-отчёт
│   ├── rules/
│   └── report/
├── scripts/              # подключение агента, сбор отчётов, запуск окружения
├── docs/                 # схемы, скриншоты и заметки к статьям
└── FLAGS.md              # список флагов (спойлеры спрятаны)
```

## Что понадобится

- Android SDK с NDK `30.0.16248370`, CMake и Ninja (подойдут те, что ставит Android Studio, или из Homebrew).
- JDK 17 или новее (для Gradle и сервера).
- Эмулятор или устройство с Android 9 (API 28) и выше. На эмуляторе VaultNotes ходит на локальный сервер по адресу `10.0.2.2`.
- `adb` в `PATH`.

## Быстрый старт

Код появляется вместе со статьями: сейчас готовы VaultNotes и агент первой части.

1. Собрать и установить VaultNotes (подробнее в [`crackme-vaultnotes`](crackme-vaultnotes)):

   ```bash
   cd crackme-vaultnotes && ./gradlew :app:assembleAudit && cd ..
   adb install -r crackme-vaultnotes/app/build/outputs/apk/audit/app-audit.apk
   ```

2. Собрать агенты и подключить агент разведки, перезапустив приложение:

   ```bash
   ./scripts/build-agents.sh
   ./scripts/attach-agent.sh --start agents/build/arm64-v8a/part1-recon/libagent_recon.so
   ```

3. Читать вывод агента в logcat (`adb logcat -s jvmti-recon`) или забрать JSON-отчёт: `./scripts/pull-report.sh`.

## Если хотите пройти VaultNotes сами

Не подглядывайте в `FLAGS.md` и код агентов: соберите приложение, поднимите сервер и попробуйте найти флаги своими инструментами. А потом сравните с тем, как их находят агенты в статьях.
